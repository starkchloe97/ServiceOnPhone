# ServiceOnPhone

A responsive, single-page Vue 3 website deployed on **Cloudflare Pages**. The contact form is handled by **Cloudflare Pages Functions** and stores enquiries in **Cloudflare D1** (SQLite). No PHP hosting, MySQL server, cPanel configuration, or separate backend hosting is required.

The layout follows the supplied Samsung & LG Service Center reference capture, with a refreshed teal-and-amber palette and replacement appliance-repair imagery.

## Stack

- Vue 3 + Vite (single page; no router or extra pages)
- Cloudflare Pages for static hosting and deployments
- Cloudflare Pages Functions for the JavaScript API
- Cloudflare D1 for storing contact and callback requests
- Wrangler CLI for local development, database setup and optional CLI deployment

## Repository structure

- src/components/ — page sections, forms, gallery, navigation and WhatsApp action
- src/config/site.config.js — all displayed business information and the frontend API URL
- src/composables/useLeadForm.js — shared frontend form submission state
- functions/api/submit.js — serverless POST endpoint at /api/submit
- functions/_shared/respond.js — consistent JSON responses
- database/schema.sql — D1 table and indexes
- wrangler.toml — Cloudflare Pages output directory and D1 binding
- dist/ — generated by the production build

## 1. Requirements

- Node.js 20.19+ or 22.12+
- npm
- A Cloudflare account

## 2. Create the D1 database (one time)

From the repository root, sign in to Cloudflare:

    npx wrangler login

Create a dedicated database for this website:

    npx wrangler d1 create service-on-phone-db

Wrangler prints a database ID. Open wrangler.toml and replace the placeholder database_id under [[d1_databases]] with that exact ID. Keep the binding name as DB and the database name as service-on-phone-db.

Do not reuse the Employee Portal's D1 database. This project needs its own database.

## 3. Initialize the database

Install dependencies:

    npm install

Create the local development table:

    npm run db:local

Create the same table in the Cloudflare D1 database:

    npm run db:remote

The schema is safe to run again because it uses CREATE TABLE IF NOT EXISTS and CREATE INDEX IF NOT EXISTS.

## 4. Run the website and API locally

The Pages Functions runtime serves the built frontend and runs the JavaScript API. Start it in terminal A:

    npm run build
    npm run api

Start Vite in terminal B:

    npm run dev

Open the Vite URL, normally http://localhost:5173. Vite forwards /api calls to the local Wrangler Pages runtime at http://127.0.0.1:8788, so the same form endpoint is used in local development and production.

Wrangler stores local D1 data in its local state directory. That directory is excluded from Git.

## 5. Deploy through Cloudflare Pages (recommended)

For the standard Cloudflare Pages Git integration, connect GitHub once and Pages automatically builds and publishes each push to main.

1. Open Cloudflare Dashboard → Workers & Pages → Create application → Pages → Connect to Git.
2. Select the GitHub repository starkchloe97/ServiceOnPhone.
3. Choose main as the production branch.
4. Set the build command to npm run build.
5. Set the build output directory to dist.
6. Keep the project root as the repository root.
7. Make sure the Pages project has the D1 binding named DB, pointing to service-on-phone-db.
8. Save and deploy.

The functions/ folder must remain at the repository root (alongside src/ and wrangler.toml). Cloudflare detects it and deploys the API functions with the site. For both Production and Preview environments, make sure the DB binding points to the intended D1 database.

### Important: use the Pages deploy command, not the Workers deploy command

The build log you shared shows Cloudflare running:

    npx wrangler deploy

That command is for deploying a Worker script. This repository is a Pages project, so it fails with the missing Worker entry-point error.

If your Cloudflare setup shows a separate **Deploy command** field (as in the log you shared), set it to:

    npm run deploy:pages

That script runs:

    wrangler pages deploy dist --project-name service-on-phone

Do not use npx wrangler deploy or wrangler deploy for this project. If you are using the normal Pages Git integration and there is no separate Deploy command field, leave that field unset; Pages automatically deploys the configured dist build output after npm run build succeeds.

The Pages project name in Cloudflare must be service-on-phone for the included command. If you chose a different Pages project name, change the --project-name value in package.json to exactly match it.

## 6. Optional: deploy from your terminal

After the Pages project named service-on-phone exists and Wrangler is authenticated, run:

    npm run deploy

This builds the Vue app and uploads dist plus the Pages Functions. To upload the already-built dist directory without rebuilding, run:

    npm run deploy:pages

## 7. How the contact form works

The Vue forms send JSON to:

    POST /api/submit

Example request:

    {
      "name": "Customer name",
      "phone": "+92 300 0000000",
      "email": "customer@example.com",
      "message": "My refrigerator is not cooling.",
      "source": "contact",
      "website": ""
    }

Allowed source values are contact, callback and service. Name and phone are required. Email is optional. The function validates and trims the input, checks the hidden honeypot, limits request size, then inserts the enquiry using a parameterized D1 statement.

Successful requests return JSON with success: true; validation errors return HTTP 422. The contact and callback forms use the same endpoint and database table.

New enquiries are saved in the service_leads table with a timestamp. You can view them in Cloudflare Dashboard → Storage & Databases → D1 → service-on-phone-db → Console, for example:

    SELECT * FROM service_leads ORDER BY created_at DESC;

## 8. Rebrand the website

Edit src/config/site.config.js to change the business name, phone, WhatsApp number and prefilled message, email, address, map link, navigation labels, hero slides, about copy, statistics, service descriptions, gallery images, footer text and opening hours.

The contact form endpoint is also configured there. You normally do not need to change it.

## 9. Security and deployment notes

- D1 credentials are not stored in the repository. Cloudflare provides the D1 binding to the serverless function at runtime.
- There is no public endpoint to read or list stored enquiries; the API only accepts form submissions.
- The endpoint uses parameterized SQL, input validation, a request-size limit and a honeypot field.
- Do not put private credentials in site.config.js or any frontend file.
- .wrangler/, local secrets and build output are ignored by Git.
- The old PHP/MySQL endpoint is no longer used. The production site runs its backend entirely on Cloudflare Pages Functions + D1.
